# Ticket 17 — first decision round accepted

The human answered “agree” to all five recommendations. These are accepted planning decisions; no runtime change or live credential use is authorized.

Accepted constraints: Runs hold only per-Run sentinels for managed service credentials (ADR 0002; Anthropic credential remains its explicit exception); ADR 0007 places Receiver/Runs in-cluster and calls for a Forwarder sidecar; ADR 0009 needs Confluence and narrow Memory authority; ADR 0010 requires enforced current-rehearsal telemetry access. Ticket 12 still owns Eyes tool selection and exact read operations; ticket 33 owns Confluence grants; ticket 21 owns Run failure/retry classification.

1. Topology: one Forwarder sidecar in the Receiver/Run pod, with separately configured service endpoints for Jira, Confluence, Grafana and Kubernetes rather than a process/container per service. Receiver and its Run children remain in their own main container; a pod can contain multiple containers. Keep service credentials and routing separate even when Jira/Confluence share an upstream host.
2. Local transport: HTTPS on loopback with a deployment-local CA and endpoint certificate, with trust explicitly supplied to supported clients. No insecure TLS bypass and no dependency on patching confluence-as to permit HTTP. Choose the exact certificate lifetime/provisioning and client trust wiring after this policy, verifying every selected client.
3. Credential scope: separate per-Run, per-service sentinels; each is valid only for its declared service and Run lifetime. Forwarder holds independently scoped upstream credentials, even for Jira and Confluence on the same site. Receiver registers/revokes sentinels through a control boundary unavailable to Runs. Do not reuse an upstream credential as a sentinel or put upstream credentials in Run mounts/environment. Exact dedicated Confluence grant comes from ticket 33.
4. Kubernetes: include a mediated Kubernetes read endpoint in this Forwarder, using a narrowly scoped service-account credential available only to it. Never mount a real Kubernetes token in the Run container. Ticket 12 decides the exact tool/read operation set; pod status remains required. No general-purpose API proxy, writes, exec, attach, port-forward or Secret reads for Runs.
5. Request enforcement: bind each endpoint to a fixed upstream origin and supported path/operation set; deny unknown operations, caller-supplied upstreams and unsafe redirect forwarding. Enforce read-only telemetry and accepted rehearsal scope through validated requests, not merely HTTP verb or a Viewer credential. Preserve explicit authorized Jira/Confluence writes. Exact query-aware enforcement belongs in the integration specification with Eyes; queries that cannot be safely scoped are refused rather than silently broadened.

Next dependent frontier: endpoint addressing without breaking native client path construction; control-channel admission/revocation/restart; TLS trust material lifecycle; network bypass prevention and upstream role proof; response/header/redirect policy and timeouts; conditional readiness when optional Confluence/telemetry fails. Do not settle these silently before the architecture choices are answered.
