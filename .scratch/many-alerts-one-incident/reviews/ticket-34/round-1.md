# Ticket 34 — first decision round accepted

The human accepted all five recommendations with “Agree.”

ADR 0009 establishes OPS authority, untrusted directory learning, draft postmortems and human-reviewed reference knowledge. ADRs 0010/0014/0017 require sanitized presentation, visible uncertainty and human review, with private scoring material outside Run access. This ticket chooses an audience presentation contract, not a dashboard implementation or new sharing permissions.

1. Presentation surface. Recommend one operator-only read-only presentation view, screen-shared by the presenter, with four clearly named sections: Incident state (OPS), Observations and hypotheses (Memory directory), Postmortem drafts, and Approved references. Keep it on the operator side outside Run-readable feeds. Do not expose a public dashboard, give attendees new account access or stream raw transcripts. The view projects verified source state rather than becoming a new Incident/Memory authority. Existing Grafana activity/timeline remains a linked complementary view, not the source of human scoring verdicts.
2. Visible card and scope. Default to the current rehearsal and selected Incident/Run. Each displayed item shows a short sanitized summary, source class, verification/review status, source revision or observation time, and a source reference the presenter may inspect. Mark hypotheses explicitly, drafts unapproved, and published guidance with actual manifest approval/version provenance. Show both “available to this Run” and “retrieved by this Run” where verified; availability is not proof of use. Count only confirmed records in each category, with gaps/unknown counts visible; do not present a total Memory count as a measure of learning quality. Rehearsal changes visibly reset context and never silently import prior artifacts.
3. Story and comparison. Use a presenter-controlled before/after sequence: show the approved references and prior cited observations actually available at admission, then show newly confirmed learning/draft work after the Run. Preserve a pinned before snapshot and visible corrections/revocations; a later state must not rewrite what an earlier Run saw. Label cold-start and Memory-assisted conditions explicitly. Demonstrate provenance and changed content, not a claim that Memory improved diagnosis or speed without a controlled comparison. Include an independent human-review summary (pending/reviewed/disputed plus qualified rationale), never private Ground truth or raw audit evidence. Human review remains distinct from execution success and from reference publication approval.
4. Refresh and failure behavior. Refresh displayed projections every five seconds when available, but retain source observation/verification times; after 30 seconds without a successful refresh, mark the affected section stale and show its last verified time. Show unknown, unavailable, revoked, write pending/failed and correction required as distinct states, not zero/empty/success. A confirmed OPS update remains visible if optional Memory fails; a failed secondary write never animates as newly learned content. Revocation/cancellation does not visually undo confirmed OPS effects. Display gaps explicitly, keep the view read-only, and avoid blocking Incident work or exposing raw errors/identity on projection failures. These are UI refresh policies, not a guarantee sources update within five seconds.
5. Replay and interaction. Provide explicit live/replay mode labels, rehearsal/Run identity and recorded sample time. A replay remains labelled throughout and cannot look like current live work. Presenter navigation may select an Incident, pin/unpin a before snapshot and inspect safe provenance, but this audience surface offers no approve/publish/retry/reset/mutation controls. Keep operational controls separate to prevent presentation clicks changing the demo. Use the same status vocabulary in replay and live views; unavailable/redacted source detail is labelled rather than silently replaced by invented text. A bounded specification follow-up defines field allowlists, projection identities, selection/refresh behavior and offline acceptance; no UI or public sharing is built here.

The consistency audit found no remaining policy choice: pinned snapshots are historical and must carry current revocation status; refresh cadence does not establish source freshness. All five recommendations are accepted. No new account grants, Confluence publication, dashboard implementation, model or demo run.
