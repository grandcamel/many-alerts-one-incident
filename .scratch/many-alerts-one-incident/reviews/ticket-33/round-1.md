# Ticket 33 — first decision round accepted

The human accepted all four recommendations with “Agree.”

ADR 0009 already fixes approved seed classes, native draft postmortems after confirmed normal Incident completion, human review before reuse, provenance, version checks and degraded operation if optional Confluence fails. ADR 0011 fixes mediated credentials/TLS. This round chooses namespace, authority and approval representation, without provisioning spaces or changing grants. CLI capability is not current tenant permission proof.

1. Namespace. Recommend two dedicated private Confluence spaces: MAOIREF for approved reference material and MAOIDRAFT for Run-authored draft postmortems. These are proposed keys, subject to collision/availability checks before provisioning, not claims that the spaces exist. References are human-curated; drafts are grouped by rehearsal where supported, but enforceable scope uses verified space/page IDs, never titles, labels or parent-tree position alone. Keep prior-rehearsal artifacts for humans without silently admitting them to a new Run context.
2. Principals and permissions. Recommend a dedicated non-admin automation principal with reference read access and only the draft-space capability required for native draft creation/read/versioned update. Use a separate human curator/operator identity for approval, publication, seed updates, archive/delete and grant changes. The Forwarder must enforce current-rehearsal registered page/Incident scope, allowed operation/body/status and prohibit publication, approval, move/copy/delete, restrictions and other unnecessary writes by Runs even if tenant-native grants are broader. Verify actual tenant grants and bypass resistance before use; a declared space key or native draft status is not an authorization boundary. If safe scope cannot be enforced, disable the affected Confluence route and disclose degraded Memory rather than grant broad access.
3. Approval and publication. Recommend human publication into the reference space as a separate curated page/version, linked back to the source Incident and draft revision; do not make a bot-owned draft reusable merely by adding an approved label. Use an operator-owned approval manifest of reference space/page ID, exact version, source provenance, reviewer and approval/revocation state. Runs cannot edit it. Serve only approved versions whose provenance can be verified; an unreviewed edit, reopening or pending correction suspends affected reuse until review. Drafts remain unapproved evidence of what the Run wrote, not an independent source of truth. This is a human curation path, not permission to publish anything during planning.
4. Seed selection and rehearsal changes. Recommend a named human curator approve a small service/dependency catalog and diagnostic runbook set selected from pinned repository/upstream source revisions. Record source URL/path, revision and review date; exclude planned-Fault postmortems, adjudication Ground truth and scoring hints. Freeze the approved reference manifest at rehearsal start for repeatable context; additions/edits normally enter the next rehearsal after review. Revocation is immediate and overrides the snapshot; affected Runs must disclose unavailable context rather than use withdrawn material. Earlier Incident-derived guidance enters only through explicit review as reference material, preserving ADR 0009's rule that reference approval does not make an old Incident eligible for Match.

Dependent frontier: concrete manifest/draft identity and conflict/recovery contracts; tenant acceptance and native draft lifecycle proof; exact operation set and field bounds; retention/human curation workflow and what the human sees. All four choices are accepted. All inspection is offline unless explicitly reported otherwise; no permission, space, page or credential changes.
