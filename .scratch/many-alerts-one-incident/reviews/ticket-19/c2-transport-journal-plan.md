# C2 transport and durable ingestion source preparation

The user directed continuation after the compiler/driver batch. This step implements the next two source components: a direct HTTP adapter and durable ingestion intent. It does not authorize C2 containers, configured backend contact, ingestion into a service, accounts, credentials, native execution, or publication. Tests use in-memory wire peers and private temporary filesystem fixtures.

Two implementation lanes own separate components; the parent joins their actual public interfaces and Sol reviews the source. Kimi K3 through headless OpenCode is requested for this new code once frozen. The earlier Fable prompt rejected by the provider is not retried or rerouted; its review remains incomplete.

The adapter must derive exact destinations from a fully regenerated configuration, validate its entire request before a socket exists, and use one direct numeric IPv4 connection. It permits only the current ingestion/read-back routes and driver headers. One absolute deadline governs connect, partial writes, status/headers and body; progress never renews the budget. No environment proxy, redirect, authentication, reconnect or request retry is included. Strict fixed-length HTTP/1.1 framing is the first supported subset; chunked, compressed, close-delimited and ambiguous responses remain unsupported until separately prepared and reviewed. Actual backend compatibility is unmeasured.

The journal lives in an explicit private operator directory. An exclusive stable lock and persistent initialization marker make any previous use, partial initialization, or missing/corrupt state a refusal to resume or reseed. It binds the entire compiled configuration and regenerated seed manifest. Intent must be persisted before invoking transport. Only final acknowledgement classification is persisted as an outcome; any persistence failure poisons the attempt and prevents later ingestion. Closing releases the lock but never removes the state or marker. These are local POSIX/filesystem operations; source tests cannot establish physical power-loss guarantees, network filesystem behavior or resistance to a malicious account owner.

Integration tests must join the real driver, adapter and journal with deterministic wire fixtures, confirm on-disk intent before payload acceptance, preserve unknown effects, stop on write failures, and refuse reopening before another connection. Full prototype tests, source hash read-back, adversarial adjudication and local commits finish the batch. Materialization/ownership, Grafana account lifecycle, C2 native policy and a complete runtime card remain subsequent work.
