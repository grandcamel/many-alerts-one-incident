## 6. Sketch of the engineer's setup skill

**Location:** `.claude/skills/demo-setup/SKILL.md`. It runs on the engineer's laptop in interactive Claude Code. It is **not** `skill/incident-sync/SKILL.md`, which is the Run's skill baked into the container. The frontmatter description should say so, and the skill must never edit that file; A3 renders it.

Rules for the skill:
- Never open `.env` (A1 denies Read/Edit on it). The engineer pastes secrets in their own editor.
- Verify through the `doctor` output only.
- Every Jira write needs explicit consent.

Stages:
1. **Orient.** Confirm the canonical repo and the basic-demo scope (Kubernetes not needed). Run `python3 -m grafana_jsm_sandbox.doctor --only host`.
2. **External gate.** Ask the engineer about each Section 4 item. For each "no" or "don't know", print the matching request from `docs/admin-requests.md`, then stop, or continue on the parts that do not depend on it.
3. **Credentials.** `cp .env.example .env`. The engineer fills in the Jira token (record the real expiry) and the output of `claude setup-token`, choosing the Enterprise org. Then run `doctor --only env,jira` (A5).
4. **Project facts.** `python3 -m grafana_jsm_sandbox.configure --project <KEY>` (A4). Show the diff and write it on confirmation. Offer the optional `rolldice` component. Re-run `doctor --only facts`.
5. **Images and stack.** Pre-pull the pinned images (A7), classifying any failures. Then `docker compose up -d --build` and `doctor --only stack,grafana` (the in-container Jira probe and the Grafana rule query).
6. **Claude probe** (opt-in, costs one call): `doctor --with-model` (A5, A10).
7. **First lifecycle.** `python3 -m grafana_jsm_sandbox.verify --replay` (A9). Then `verify --live`, which stops traffic and waits for Firing, create, repeat and resolve. Point the engineer at `docker compose logs -f demo`, now with `[FAILED]`/`[retry]` lines (A6), and at the queue URL printed by configure.
8. **Clean reset.** `python3 -m grafana_jsm_sandbox.reset` (dry run, A8) → `--yes`. Confirm "queue empty of demo Incidents" and that traffic is running.
9. **Hand-off.** Point to the runbook's presenting section. Record the token expiry date. Explain teardown (`docker compose down`, revoking the tokens).

**Commands from Section 2 it depends on:** `doctor` (A5), `configure` (A4), `verify` (A9), and the marker-scoped `reset` (A8). They sit on top of `demo_config`/`.env` as the single source (A2) and the rendered Skill (A3).
